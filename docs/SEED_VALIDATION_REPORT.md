## 3. 缺陷清单

### 3.1【P0】`"好公司?"` 中文子串误判——质地"不好"的股票被判定为好公司

```
judgment_chain.py:864
  "three_part_conclusion": f"好公司? 【{'是' if '好' in quality_verdict else '否/存疑'}】 · ..."
judgment_chain.py:619  （Lint 纠偏分支存在同一写法）
```

`quality_verdict` 的取值域是 `{"好", "部分好", "不好"}`，而 `"不好"` **包含子串 `"好"`** → 判定为"是"。

**命中情况（10 只中 5 只，50%）：**

| 代码 | quality_verdict | 三分结论输出 | 应有输出 |
|:---|:---:|:---:|:---:|
| 601398 工商银行 | 不好 | 好公司? 【**是**】 | 否/存疑 |
| 000001 平安银行 | 不好 | 好公司? 【**是**】 | 否/存疑 |
| 688981 中芯国际 | 不好 | 好公司? 【**是**】 | 否/存疑 |
| 603959 ST百利 | 不好 | 好公司? 【**是**】 | 否/存疑 |
| 601718 ST际华 | 不好 | 好公司? 【**是**】 | 否/存疑 |

这是**最容易误导用户的一处缺陷**：决断卡最显眼的三分结论，直接否定了同一张卡里 ❶ 支柱得出的"不好"判定。

> 该缺陷与早已识别的"档位用中文子串做控制流"（`act_key` 用 `"回避" in decision_gear`）**同源**。修复应一并进行：把 `quality_verdict` / `odds_verdict` / `path_verdict` / `decision_gear` 全部改为 `enum.StrEnum`，用显式映射表替代子串匹配。

**建议改法**：`quality_verdict` 改为枚举后，`"是" if quality_verdict is QualityVerdict.GOOD else "否/存疑"`；最短平快的止血是先判否定：`"是" if quality_verdict == "好" or quality_verdict == "部分好" else "否/存疑"`。

### 3.2【P0】Beneish / Altman 模型对金融业与硬科技企业系统性误报

| 代码 | 致命/高危红旗 | 现实合理性 |
|:---|:---|:---|
| 601398 工商银行 | 🔴 **财务操纵高风险 (Beneish M-Score 超标)** | 国有大行，受银保监会严格监管，财务操纵先验概率极低 |
| 000001 平安银行 | 🔴 **财务操纵高风险 (Beneish M-Score 超标)** | 同上 |
| 688981 中芯国际 | 🔴 **破产高危区域 (Altman Z-Score 极低)** | 账上现金充裕的国家战略级半导体企业 |
| 300750 宁德时代 | 🟠 财务状况脆弱 (Altman Z-Score 灰色区) | 全球动力电池龙头，现金流强劲 |

**根因**：Beneish M-Score 与 Altman Z-Score 都是**面向制造业/一般工商业**设计的经验模型，其变量依赖应收账款、存货、折旧、留存收益等科目：

- **银行业**没有传统意义的"应收账款/存货"，资产负债结构是"吸收存款—发放贷款"，代入原模型必然得到畸变的 M 值与 Z 值；
- **半导体/重资产科技**的 Z 值对"留存收益/总资产"高度敏感，高资本开支与累计亏损期会机械触发"破产高危"。

**这是"模型不适配 A 股行业结构"最典型的一例**，且后果严重——它让**最安全的国有大行被判为财务操纵高风险**，同时让系统对真正的绩差股失去区分度（ST百利 10 条红旗与工商银行 2 条红旗，在"是否回避"上无法区分，两者都只是"回避"）。

**建议**：
1. 引入 `industry` 分类（申万一级）作为**模型准入开关**：银行/证券/保险禁用 Beneish 与 Altman（改用 CAMEL 或资本充足率/不良率等金融专属指标）；
2. 对 Altman Z 增加"非金融 + 营运资本为正"前置条件，不满足则**弃权**而非给分（符合 NFR-02 的"缺失特征自动弃权"）；
3. 至少把这两条在金融业上降级为 `LEVEL_MEDIUM` 并注明"模型不适用，仅供参考"。

### 3.3【P0】亏损股净利润被判定为"已核验"，并进入 DCF/SOTP 估值

```
judgment_chain.py:294-296
  if raw_ni is not None and raw_ni != 0:
      net_income_latest = raw_ni / 1e8
      ni_is_verified = True
```

判据是 `!= 0`，**并未排除负数**。三只 ST 亏损股（605336 / 603959 / 601718）实测 `derivation_present = true`，即系统用**负净利润**跑完了 DCF 与 SOTP 双锚：

- **601718 ST际华**：一家 ST 亏损公司，赔率判定输出 **`买完完美未来`**（意为"市场定价已透支最乐观情景"）。该结论在语义上成立，但**推导过程是错的**——它是用负利润基数反推出来的，而非基于真实盈利能力。
- **605336 \*ST帅电**：赔率判定 `已被价格计入`，质地判定 **`部分好`**。一只净资产承压的 \*ST 股被评为"部分好"，说明 ❶ 支柱的质地五问在亏损情形下缺乏硬闸门。

此外 `judgment_chain.py:344` 的 `price/sotp_ps` 与 `price/dcf_ps` **没有零值保护**（同文件 `:391` 却有 `sotp_ps > 0` 的守卫，属遗漏）。若某只亏损股推出的 `sotp_ps == 0`，此处会抛 `ZeroDivisionError`。本次 10 只样本未触发，但风险客观存在。

**建议**：
1. `:294` 改为 `if raw_ni is not None and raw_ni > 0:`，负值与零一律走未核验分支；
2. 增加"亏损股"专用判定态 `未核验(净利润为负)`，并强制 `odds_verdict` 为不可计算、`position_cap = 0`；
3. `:344` 补零值守卫。

### 3.4【P0】Tier 2 排雷完全空转——质押率从未联网采集

```
eltdx_collector.py:445-450
  res = {
      "pledge_ratio": 0.0,      # ← 硬编码，get_f10_governance_and_concept 从不取质押数据
      ...
  }

filter_audit.py:29-30
  pledge_ratio = float(gov.get("pledge_ratio", 0.0) or 0.0)
  if pledge_ratio > config.PLEDGE_FATAL_RATIO:   # 0.0 > 0.70 恒为 False
```

实测证据：对 **30 只 ST 样本**调用 `get_f10_governance_and_concept`，`pledge_ratio` **全部返回 0.0**；决断卡中亦无质押字段（`pledge_ratio_seen: null`）。

**后果**：
- `filter_audit` 是三层漏斗的 Tier 2 一票否决层，但它唯一的判据恒不成立 → **Tier 2 事实上永不剔除任何标的**（除接口异常外），三层漏斗退化为两层；
- `AuditEngine._check_governance` 中的"控股股东高比例质押暴雷风险"致命红旗**在生产中永不触发**；
- 高质押是 A 股**最常见、最具杀伤力**的暴雷因子之一（平仓踩踏），系统对此完全无感知；
- 同时违反了 NFR-02：用 `0.0` 这个"看起来正常"的值**伪造了"无质押"这一事实**，与数据缺失不可区分。

**建议**：
1. 接入真实质押数据源（F10 的股东质押/股权质押通道），采集失败返回 `None` 而非 `0.0`；
2. `filter_audit` 扩展为多因子排雷：质押率 + 商誉/净资产比 + 审计意见类型 + 有息负债/EBITDA + 违规处罚；
3. 在质押数据不可得时，按 fail-closed 标记 `audit_status="UNVERIFIED"` 并**降权**，而非当作 0 放行。

### 3.5【P1】输出自相矛盾：同一张卡上"财务操纵高风险"与"便宜(有余地)"并存

000001 平安银行：`flags_fatal = 1`（Beneish 财务操纵高风险）→ 档位"回避"，但 ❸ 支柱 `odds_verdict = 便宜(有余地)`，三分结论"好价格? 【是】"。

这意味着**系统用被自己判定为"可能被操纵"的财务数据，算出了一个"便宜"的估值结论**。估值模型未与审计红旗联动。

**建议**：`_build_pillar_3_odds` 接收 `flags` 参数，命中财务操纵类致命红旗时，把 `odds_verdict` 强制置为 `未核验(财报可信度存疑)` 并跳过双锚计算。

### 3.6【P1】100% 零仓位——档位校准缺失，"买入"路径从未被真实触发

10 只样本 `position_cap` 全为 `0.0`，无一只进入买入档。归因：

- 8/10 只 `path_verdict = 高尾险·不可承受`（主力阶段多为"无抵抗阴跌出清期"）；
- 剩下 2 只（600519、920002）路径可承受，但 `odds_verdict = 已被价格计入` → 档位"不追高(贵但优质)"，cap 仍为 0。

**问题**：本套件无法验证"买入档位是否正确"，因为真实样本中它从不出现。`act_key = "BUY" if position_cap > 0` 这条分支、以及 `期权仓(小)`/`核心仓` 等档位，全部缺乏真实数据回归保护。

**建议**：
1. 增加"买入路径"的注入式回归测试（构造满足 状态↑变好 + 赔率便宜 + 路径可承受 的合成样本，断言档位与仓位映射正确）；
2. 检视 ❹ 支柱是否过度悲观：本次 `micro_degraded` 全为 false（微观数据正常），却有 5 只被判"无抵抗阴跌出清期"，需核对 5 分钟 K 线的时段对齐与状态机打分阈值是否对大盘股失配。

### 3.7【P1】北交所标的被成交额门槛系统性排除

```
filter_liquidity.py:45
  is_gem_star = code_num.startswith(("300", "301", "688"))
filter_liquidity.py:49
  amt_threshold = config.LIQUIDITY_GEM_MIN_AMOUNT if is_gem_star else config.LIQUIDITY_MAIN_MIN_AMOUNT
```

板块判定只有"双创 / 其他"两档，**北交所（920/8/4）落入"其他"，适用主板 5 亿门槛**。而 `:66` 的 `is_bse` 判定（用于涨幅上限 30.5%）说明作者清楚北交所差异，只是成交额档位漏配。

北交所整体日成交额远低于主板（本次种子 920002 万达轴承总市值仅 36.6 亿），5 亿门槛会使**北交所标的几乎全数出局**，与系统宣称覆盖全市场不符。

**建议**：`config` 增加 `LIQUIDITY_BSE_MIN_AMOUNT`（建议 0.5 亿量级），并在 `filter_liquidity` 中按 MAIN/GEM_STAR/BSE 三档取值。

### 3.8【P1】Tier 2 只审计前 15 只标的

```
filter_audit.py:18,21
  top_audit_count: int = 15
  targets = candidates[:top_audit_count]
```

第 16 名之后的候选**完全不经过排雷**就进入 Tier 3 排序与最终推荐池。若排序靠后的标的恰好被选中，它将带着未排雷状态输出。

**建议**：`top_audit_count` 默认改为覆盖 Tier 1 全部输出，或至少与 `--top` 参数联动，并在日志中显式披露"未排雷数量"。

### 3.9【P2】换手率门槛事实上排除了全部大盘蓝筹

`MOMENTUM_MIN_TURNOVER_RATE = 7.0`。实测：600519 茅台换手率 0.18%、601398 工行 0.08%、000001 平安银行 0.51%、300750 宁德时代 0.53%、688981 中芯国际 0.81%——**全部远低于 7%**。

这意味着三层漏斗的 Tier 1 会把所有超大盘权重股一律剔除。若这是"短线题材打板"的明确定位则合理，但系统同时对外宣称"买方深度投研"，两者定位需要澄清。

**建议**：在 `docs/ARCHITECTURE.md` 明确声明 `screen` 的适用域为"短线高换手题材接力"，并考虑增加按市值分档的换手率阈值（大盘股 1%~10%，小盘股 7%~28%）。

### 3.10【P2】降级与门控路径缺乏真实数据验证

本次 10 只样本 `data_health.failed` 与 `degraded` **均为空**，`lint_ok` 全为 `true`。说明：fail-closed 的三条关键路径（微观降级、财务缺失、Lint 拦截）在本次跑批中**一条都没有被真实触发**，其正确性只能由既有单元测试保证。

**建议**：保留本套件的"真实数据"定位，同时明确标注其覆盖边界；降级行为由 `tests/test_audit_round2_fixes.py` 的注入式用例守护，两者互补，不可互相替代。

## 7. 附：本套件的能力边界

`tests/test_seed_universe.py` 定位为**常驻真实数据回归套件**，它守护的是：

- 全链路在各板块/各市值档位下能否跑通（防结构性崩溃）；
- 三轮审计沉淀的风控不变量是否依然成立（防逻辑退化）；
- 板块、涨跌停、市值档位等确定性判定是否正确（防规则漂移）。

它**不**覆盖（由 `tests/test_audit_round2_fixes.py` 等注入式用例守护）：微观降级、财务缺失、Lint 拦截、买入档位映射。两套互补，缺一不可。

由于实时数据逐日变动，套件内**不存在**对价格、评分、红旗数量的硬断言；这类波动量的合理性判断由本文档的人工评估承担。
