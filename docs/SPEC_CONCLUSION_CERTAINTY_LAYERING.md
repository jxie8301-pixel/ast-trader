# 规格：结论确定性分层与时效性治理（P1）

> 起因：第三方评审指出系统生成的个股研报「把某一时间切片的微观交易信号，
> 以过高的确定性固化成了行动指令」，并指出三条具体缺陷：
> 时效性偏误、估值框架傲慢、缺少「事实/判断/指令」确定性分层。
> 经代码核查（见 `docs/UNIMPLEMENTED_WORKLIST.md` D-34），三条均指向真实缺口。

---

## 1. 目标与预期成果

### 1.1 目标

在**不改变任何计算口径、不改变任何阈值、不改变选股结果**的前提下，
修正研报「结论表达方式」，使读者能够区分：

1. **哪些是可直接核验的数据**（事实）
2. **哪些是基于数据的推论**（判断）
3. **哪些是建议而非纪律**（指令）
4. **这些结论基于什么时点、什么假设、不含什么**

### 1.2 预期成果

| 编号 | 成果 | 对应评审批评 |
|:--|:--|:--|
| G-1 | 估值区间的**假设前提与排除项**在报告中可见，不再被当作无条件「合理价」 | 框架傲慢 |
| G-2 | 微观资金面结论**始终**携带时效性声明，而非仅在数据降级时才提示 | 时效性偏误 |
| G-3 | 「证伪线」语义不被弱化为单纯价格阈值，保留「假设可被推翻」含义 | 确定性分层 |
| G-4 | 高置信度结论同样标注不确定性（当前实现是**置信度越高越不提示**） | 确定性分层 |

### 1.3 非目标（明确不做）

- ❌ 不修改 `PLEDGE_*`、`PLEDGE_OWN_*` 等任何风控阈值
- ❌ 不修改主力阶段判定逻辑（`main_force_engine.py` 的状态机与阈值）
- ❌ 不修改 `Q 值 / smart_vwap` 的计算公式
- ❌ 不改变选股漏斗结果与四轨输出
- ❌ 不引入 AI 参与（本批次为纯确定性逻辑改动）

## 3. 输入、输出与关键约束

### 3.1 输入

| 输入 | 来源 | 说明 |
|:--|:--|:--|
| `derivation` | `core/derivation.py:generate_standard_derivation` | 含 `sotp` / `dcf` / `p_f_n` / `share_count`，已有 `basis`、`falsify`、`components` 等元数据 |
| `anchor_range` | `core/derivation.py:432-437` | 含 `divergence_note`（本次启用） |
| `micro` | `core/main_force_engine.py` | 含 `main_force_confidence`、`is_transitional`、`suggested_pos_cap` |
| `is_micro_degraded` | 决断链 | 微观数据降级标记 |

### 3.2 输出

| 输出 | 类型 | 约束 |
|:--|:--|:--|
| `pillar_3_odds` | `str` | 追加假设要点，**必须**保持原有四行（`判定` / `P=F+N` / `反向 DCF` / `锚点`）不变 |
| `pillar_4_path` | `str` | 首行时效性声明**恒非空** |
| 决断卡整体 | `dict` | 必须通过 `core/schemas/decision_card.schema.json` 校验 |

### 3.3 关键约束

**C-1 计算零改动**：本次**禁止**修改任何数值计算。所有改动限于字符串拼装与文案。
> 理由：评审批评的是"表达方式"，不是"算法"。改算法会让本批次与风控阈值调整纠缠不清。

**C-2 渲染层兼容**：`html_renderer.py:507-523` 以 `white-space: pre-wrap` +
`html.escape` 渲染支柱文本，**不解析 Markdown**。
> 推论：F-1 的假设要点**只能**用纯文本 `• xxx` 形式，**不得**用 `| 表头 |` 表格语法，
> 否则读者会看到裸管道符。Markdown 表格式假设表推迟到 F-8（需先改渲染器）。

**C-3 措辞替换表安全边界**（`plain_language.py:152-156`）：
两字以内中文词**一律不得**进 `SUBSTITUTIONS`（中文无词边界，会命中子串）。
F-5 的替换目标「证伪线」为三字词，安全。

**C-4 向后兼容**：决断卡字段名**只增不改**。若需改名（如 F-2），
保留旧字段并双写，避免破坏 `reports/` 已有产物与 `lint` 规则。

**C-5 性能**：支柱文本拼装为 O(1) 字符串操作，单卡开销 < 1ms。
不得引入额外网络请求或文件 IO。

**C-6 错误处理**：`derivation` 中任一字段缺失时，对应要点输出 `未核验(字段缺失)`，
**严禁**用默认值伪造假设（沿用既有 NFR 数据纪律）。

**C-7 Lint 规则兼容**：`lint/validator.py` R16 检查正文价区与 `anchor_range` 一致性。
F-2 改名后正文仍须包含相同数值，确保 R16 不误报。
